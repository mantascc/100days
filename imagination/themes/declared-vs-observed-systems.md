# What
Is a house style something you write down, or something you notice? The
sketchbook has now answered both ways about the same material, deliberately.
[69-clear-channel](../../69-clear-channel/) and
[70-clear-channel-2](../../70-clear-channel-2/) formalise the visual language
as a system — tokens, rules, a canon. `sketch-field-notes` reframes the
identical material as *observed*: recurring plumage rather than declared
rules, with every claim carrying a citation and every rule followed by the
exception where it stopped holding.

Neither is wrong, which is why this stays open. A declared system is legible
to other people and can be handed over; it also freezes taste at the moment of
writing and quietly turns future work into compliance. An observed system
stays true to the practice and cannot be handed to anyone, because it is a
description of one person's habits and has no authority outside them.

# Trace
- [69-clear-channel](../../69-clear-channel/) — the language stated as a system.
- [70-clear-channel-2](../../70-clear-channel-2/) — the same, refined; reads as architected.
- [sketch-field-notes](../../daily-sketch/sketch-field-notes/) — the counter-position: field notes on a style that was never designed.

# Charge
Medium and rising. The same tension is now load-bearing outside the sketches
— the [design-system bundle](../../design-system/SPEC.md) resolves it by
fiat ("permanence is earned, not declared") and the
[Imagination SPEC](../SPEC.md) leans the other way by keeping Threads
*recognised, not declared*. Two specs and three sketches disagreeing about the
same question is exactly the condition a Theme is for. Do not close it.

# Prompts
- A sheet that shows both readings of one token side by side — the rule as written, and the twenty instances it was induced from.
- Let the observed system *contradict* the declared one in public: render the exceptions as the primary content and the rule as a footnote.
- A style guide with a decay term — claims that expire unless a new sketch re-cites them.
